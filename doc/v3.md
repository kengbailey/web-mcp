# Web MCP v3: output contract, paging, caches, providers

## Why v3
v2 returned a JSON envelope (`schema_version`, `status`, `page`, `meta`…) as both
structuredContent and a text copy, plus a pydantic output schema per tool. OpenWebUI
resends the catalog every turn and forwards both copies when they differ; Codex and
Claude Code forward only structuredContent. v3 returns **one compact text block** and
**no output schemas** — the catalog shrank from 25.6 KB to ~7 KB (see `doc/bench.md`).

## Output contract
- **Content** (`fetch_content`, `read_content`, transcripts, forum threads): a header line,
  a blank line, then the body.
  `Title · url · source · [note] · chars 0–8000/84213 · next: <cursor>`
  The last chunk ends with `· end`; a document that fits shows `· 3130 chars` and no cursor.
  A forum page that ends with more thread pages shows `next page: <cursor>`.
- **Listings** (`search`, `search_videos`, `search_reddit`, `fetch_subreddit`): numbered rows,
  then `more: <cursor>` only when more exists. Continue by calling the same tool with
  `cursor` (saved query/filters are reused; other arguments are ignored).
- **Comments** (Reddit/YouTube): one line per comment, indented by depth; long bodies end
  with `[+1.8k chars: <cursor>]` → `read_content(cursor)`.
- **Errors**: `ERROR <CODE>: <message>` with `isError=true`. Codes: `INVALID_ARGUMENT`,
  `NOT_FOUND`, `NOT_CONFIGURED`, `RATE_LIMITED`, `UPSTREAM_TIMEOUT`, `UPSTREAM_ERROR`,
  `UPSTREAM_BLOCKED`, `CURSOR_EXPIRED`, `TOO_LARGE`, `UNSUPPORTED_CONTENT`, `UNAVAILABLE`,
  `INTERNAL_ERROR`.
- Diagnostics never appear in the text; nulls/defaults are omitted.

## Defaults and limits
| | |
|---|---|
| Content chunk | 8,000 chars (`max_chars` 500–20,000; `DEFAULT_MAX_CHARS` env) and ≈ chars/4 tokens (non-ASCII counts 1 token/char) |
| Listing `limit` | 1–10 (search 5, Reddit 5, comments 10) |
| Search snippet | ≤300 chars, query-relevant Exa highlights |
| Exa search type | `fast` (`EXA_SEARCH_TYPE`: auto, lite, neural…) |
| Inline comment/body | ≤500 chars; post body first chunk 8,000 |
| Download cap | 8 MiB HTML/text, 32 MiB PDF |
| Deadlines | 45 s per tool; `fetch_youtube_transcript` 300 s (progress notifications are sent) |

## Caches and cursors (process-local; lost on restart)
| Data | TTL |
|---|---|
| Extracted page/PDF/thread | 15 min (mode switches and `read_content` never refetch) |
| Exa results (10 per paid call) | 10 min |
| Reddit listings/posts/comments | 5 min |
| YouTube extraction info | 1 h |
| Transcripts (captions or STT) | 24 h |
| Cursors | 15 min, 12-char random, scoped to the caller (bearer-token hash; anonymous LAN callers share one scope) |

Concurrent identical requests share one upstream call. A cursor whose document was evicted
returns `CURSOR_EXPIRED`; repeat the original call. Multi-worker deployments would need
shared storage or sticky routing.

## Web fetching
Static fetch (pooled client, manual redirects with SSRF re-validation) → trafilatura fast
extraction (full extraction only for short results) → headless Chromium only when needed:
403/429/503, bot challenge, empty/short text or a JS app shell. Hosts that needed the browser
are remembered for an hour; their browser cookies are reused by the static client.
PDFs are extracted locally (pypdfium2). There is no third-party reader fallback.

Forum threads on XenForo (XDA and others) render as compact posts. Quotes of other posts
collapse to one line; the author's own boxed sections stay whole. `read_content` continues
into the next thread page.

Only public HTTP(S) targets without credentials are fetched; private/loopback/reserved
addresses are rejected at every hop and for browser sub-requests. The direct static client
also checks the address it actually connects to, so DNS rebinding cannot reach internal
hosts. Two paths are not rebinding-proof: Chromium resolves names itself, and behind
`PROXY_URL` the proxy does. Public deployments should also restrict egress at the network.

Cursors are scoped to the authenticated principal (client, issuer, subject), so token
rotation does not break pagination; tokens without a subject are scoped per token.
Speech-to-text runs at most two jobs at once; a job keeps running (up to 15 min) after its
caller times out or disconnects, and its transcript is cached, so a retry never pays twice.

## YouTube and STT
One yt-dlp extraction per video (cached) supplies metadata, captions and the audio format.
Transcripts: captions via youtube-transcript-api, then json3 captions from the extraction,
then speech-to-text when allowed (`source="stt"` forces it; `fallback_to_stt=false` disables).
STT downloads the smallest original-language audio track without re-encoding, splits files
over 24 MB with `ffmpeg -c copy` into 15-minute segments, and transcribes up to 4 segments
concurrently via `POST {STT_ENDPOINT}/audio/transcriptions`. It asks for `verbose_json`, so STT transcripts get the same
`[m:ss]` paragraphs as captions (plain JSON is retried for providers that refuse it).

| Variable | Default |
|---|---|
| `STT_ENDPOINT` | `https://openrouter.ai/api/v1` |
| `STT_MODEL` | `nvidia/parakeet-tdt-0.6b-v3` (25 European languages) |
| `STT_FALLBACK_MODEL` | `openai/whisper-large-v3-turbo` (other languages) |
| `STT_API_KEY` | falls back to `OPENROUTER_API_KEY` |
| `STT_MAX_SECONDS` | 14400 |

OpenRouter limits: 25 MB per request and a 60 s upstream timeout. Comments need
`YOUTUBE_API_KEY`; metadata uses it when present, else the extraction.
